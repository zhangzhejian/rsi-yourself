## 1. Agent 的 RSI 具体怎么做

### 1.1 改什么：三个面

MetaRSI 把系统写成 S = (D, θ, H)：

| 面 | 内容 | 对应算子 | 成本特征 |
|----|------|---------|---------|
| D 数据 | 执行轨迹、合成并验证过的训练记录 | Data-RSI | 模型调用 |
| H 脚手架（harness） | system prompt、memory、tools、skills、MCP | Harness-RSI | 每次推理都要付上下文成本 |
| θ 权重 | 模型参数（LoRA 训练） | Model-RSI | 一次性训练成本，推理时免费 |

### 1.2 怎么改：一次循环（loop kernel）

`Observe → Diagnose → Propose → Validate → Execute → Select → Export`

- 只有 Diagnose 和 Propose 由模型完成；其余步骤由确定性代码完成。
- 原则：**模型负责提议，代码负责裁决**；任何组件都不评估自己的输出。
- Harness 补丁只有严格优于历史最好时才晋升，并且有复杂度上限。

### 1.3 按什么顺序改：组合规则

- H 或 θ 改变后，系统能力变了，旧数据就过期了，需要重新采集。
- 允许 D→H、D→M、H→D、M→D、M→H；禁止 H→M（用 harness 变更前的数据训练权重）。
- M→H 是"冗余调和"：权重已经学会某个行为后，删除对应的脚手架条目，释放上下文。

### 1.4 递归在哪里：三层结构

1. **L1 Kernel**：执行一次改进循环。
2. **L2 调度**：水平轴决定下一步用哪个算子；垂直轴改写某个算子的提议策略。
3. **L3 Meta**：每个周期结束后修改调度策略。L3 自身固定，递归到此终止。

评测器、held-out 集、发布规则和账本在**所有层的写入面之外**。

### 1.5 实证结论和限制

- **放大器，不是来源**：没有闭环能创造能力，增益都是导入的（MetaRSI Law 5，三篇论文一致）。
- **验证决定前沿**：69% 的 RSI 系统依赖机器可检查的目标；没有外部验证时，harness 演化甚至低于直接采样。
- **要和同预算基线比**：在 Terminal-Bench 上，harness 演化打不过同预算的 parallel sampling，held-out 收益为 0。
- **Context 只能选择，control 才能改变**：只改输入的 context harness 只能在已有行为里选；需要计算、计数、拦截动作的偏好必须用 control 机制。
- **Memory 不是越多越好**：违反率随 memory 条数呈 U 型，约 10 条时最好。
- **自我改进容易"记住修复"而不是"提炼策略"**：写入的多是具体任务的步骤，真正的难题不受影响。
- **收益递减**：MetaRSI 每个周期的增益从 +7.2 降到 +1.4；meta 层只能把平台期推迟一个周期。

## 2. 映射到人

### 2.1 三个面

| Agent | 人 | 例子 |
|-------|-----|------|
| D 数据 | 经历的记录和提炼 | 日志、时间记录、复盘、错题本、他人反馈 |
| H 脚手架 | 外部结构 | 规则清单、日历模板、工具、物理环境、承诺机制、AI 助手 |
| θ 权重 | 内化的能力和习惯 | 技能熟练度、自动化的习惯、直觉判断 |

成本特征也成立：依赖外部规则每次都要消耗注意力（类似上下文成本）；内化之后不再需要提醒（类似推理时免费），但内化需要一次性的练习投入。

### 2.2 三个算子

| 算子 | 对人的含义 |
|------|-----------|
| Data-RSI | 从经历中提炼**经过验证**的经验：只有反复出现、有证据的模式才记录为结论 |
| Harness-RSI | 修改规则、流程、工具和环境 |
| Model-RSI | 刻意练习，把行为从"靠规则提醒"变成"自动完成" |

组合规则的对应：

- **M→H**：习惯养成后，删除对应的提醒和规则，避免规则清单无限增长。
- **H→M 禁止**：改变环境或流程后，旧的表现数据不再代表现状。先在新条件下重新记录，再设计练习。

### 2.3 一次循环

| 步骤 | 对人的做法 | 谁执行 |
|------|-----------|--------|
| Observe | 采集记录：日历、任务、对话历史、自评、可穿戴设备 | 尽量自动采集 |
| Diagnose | 从记录中找失败模式并归因 | 人 + AI |
| Propose | 提出**一个**实验：假设、改动、周期、判定标准 | 人 + AI |
| Validate | 执行前检查风险、成本、是否可撤销 | 人 |
| Execute | 按周期执行，同时记录是否真的执行了 | 人 |
| Select | 按**实验前写下的**判定标准比较 | 规则 + 独立评审（AI 或他人） |
| Export | 有效的写入规则库或 self-model；无效的回滚并记录原因 | 人 + AI |

"模型提议、代码裁决"对应到人：**提议可以靠直觉，裁决必须靠事先冻结的标准和数据**。

### 2.4 三层结构

1. **L1**：单个实验，周期一到两周。
2. **L2**：决定这一轮做哪类改进（记录、改环境、刻意练习），以及改进提议的方法（例如复盘问题清单）。
3. **L3**：季度级复盘，修改 L2 的调度方式。L3 的固定部分是价值观、底线和评价规则的修改流程。

### 2.5 保护边界

人最容易作弊的地方在评价器：结果不好时改指标、换口径、事后合理化。对应做法：

- 每个实验开始前写下指标和判定标准，实验期间不修改。
- 判定由 AI 或他人对照原始记录完成，不只看本人的自评。
- 保留 held-out：在真实场景中检验，而不只在专门练习的场景中检验。
- 修改评价标准走单独流程：写明原因，建立新基线，不和旧结果直接比较。
- 首次失败不抹掉；组合改动标记为组合实验，不归因到单一改动。

## 3. 人和 agent 的关键差异

| 差异 | Agent | 人 | 设计含义（推测） |
|------|-------|-----|----------------|
| 基线 | 同预算 parallel sampling | 不能并行，只有一条时间线 | 实验前先有一段"不改动"的基线期，测量自然波动；警惕霍桑效应（被观察就变好）和回归均值 |
| 噪声与样本 | 可跑几十上百个任务 | 一个人，周期以周计 | 一次只改一个变量；效应要大于基线波动才算数 |
| 执行 | 补丁写入即生效 | 补丁本身有执行失败率 | 分开记录"是否执行"和"执行后是否有效"，否则无法区分方案无效和没做 |
| Context vs control | 写进 prompt 只能选择已有行为 | "知道"不等于"做到" | 关键行为优先用 control 机制：环境强制、自动化、承诺机制、他人检查，而不只写一条规则 |
| Memory 规模 | 约 10 条最好 | 规则太多同样记不住 | 生效规则设上限（例如 10 条），定期合并和删除 |
| 能力来源 | 增益都是导入的 | 同样 | 闭环只能放大已有能力；新能力要从外部导入：书、课程、导师、AI |
| 验证 | 可验证领域先闭环 | 健康、产出比幸福感、关系更容易测量 | 第一个领域选反馈清晰、可量化的 |
| 目标 | 目标漂移是缺陷 | 价值观变化可以是合理的 | L3 需要包括"重新审视目标"，但改目标要显式记录，不能借此掩盖失败 |
| 自我描述 | 自我描述会过期（Law 2） | 自我认知偏差更大 | self-model 定期用数据重写，而不是只追加 |

## 4. 初步设计原则

1. **先建评价闭环，再做改进**：选定领域后，先采集一段基线数据。
2. **一次一个实验**：每个实验写明假设、改动、周期、判定标准、执行记录方式。
3. **判定标准实验前冻结**，裁决对照原始数据，由 AI 或他人参与。
4. **三份独立读数**（借鉴课程 RSI 方法）：结果指标、执行依从度、成本（时间、精力、副作用）。
5. **关键行为优先用 control 机制**，规则只用于选择方向。
6. **规则库有上限**，习惯内化后删除对应规则（M→H）。
7. **区分"记住修复"和"提炼策略"**：只把可迁移的策略写进规则库。
8. **新能力从外部导入**，闭环负责筛选和放大。
