rsi-yourself · 方法梳理 · 2026-10-30

把 agent 的自我改进方法，用到人身上

RSI：让一个系统自己找问题、自己改、自己验证，并且连“怎么改”也一起改进。

RSI 是 Recursive Self-Improvement 的缩写，中文叫递归自我改进。下面先拆开 agent 的 RSI 有哪五块，再看人的 RSI 怎样一一对应。

第一部分

Agent 的 RSI 由五块组成 来自论文

  1. 01

    改什么

    可以被修改的东西

    一个 agent 表现好不好，由三样东西决定。RSI 改的就是这三样。

    经验数据它做过的任务留下的记录，可以整理成学习材料。
    外部配置模型之外的说明书和工具箱：提示词、记忆、工具、技能。改起来快，但每次运行都要占用上下文。
    模型本身模型通过训练学会的能力。改起来慢、成本高，学会以后不再额外占用。
    论文术语：Data / Harness / Model
  2. 02

    怎么改

    一轮改进循环

    每一轮都按固定步骤走：

    1. 做任务
    2. →
    3. 看记录找问题
    4. →
    5. 提出一个修改
    6. →
    7. 检查是否合规
    8. →
    9. 用新版本再做
    10. →
    11. 和原来比较
    12. →
    13. 更好就保留

    关键：提出修改的是模型，判断好坏的是固定的程序。提出修改的一方不能给自己打分。

    论文术语：loop kernel
  3. 03

    怎么判断变好

    独立的评价标准

    一套事先定好的测试和打分规则。另外留一批改进过程中从没用过的题，用来检验改进是否真的通用，而不只是记住了练习题。

    关键：这套标准放在改进过程够不着的地方，任何一轮改进都不能修改它。

    论文术语：sealed evaluator / held-out set
  4. 04

    先改哪个

    每一轮的选择

    每一轮决定改哪一样：整理数据、改配置，还是训练模型。

    规则：改了配置或模型之后，系统已经变了，之前的记录要重新收集。模型学会某个行为后，删掉配置里对应的提示，避免越堆越多。

    论文术语：scheduler / 组合规则
  5. 05

    改进“改进方法”

    元改进

    定期回头检查“找问题、提修改的方法”本身好不好，再改进它。“递归”两个字就来自这一块。

    关键：递归要有终点。最外层的规则固定不变，否则就没法验证。

    论文术语：Meta 层
第二部分

人的 RSI 对应的五块 推论，待验证

把同样的结构套到人身上，编号和第一部分一一对应。

  1. 01

    改什么

    决定你表现的三样东西
    经历记录日志、时间记录、复盘、别人的反馈。对应经验数据。
    外部结构规则清单、日历安排、工具、物理环境、AI 助手。改起来快，但每次都要花注意力去遵守。对应外部配置。
    内化能力习惯、技能熟练度、直觉判断。养成慢，养成后不再费力。对应模型本身。
  2. 02

    怎么改

    一个个小实验
    1. 记录
    2. →
    3. 从记录里找问题
    4. →
    5. 设计一个小实验
    6. →
    7. 检查风险和能否撤销
    8. →
    9. 执行一到两周
    10. →
    11. 按事先的标准比较
    12. →
    13. 有效就保留

    小实验要写清三件事：改什么、做多久、怎么算成功。执行时同时记录有没有真的做，否则分不清是方法没用，还是没做到。

    关键：想法可以靠直觉，判断好坏必须靠事先写下的标准和记录。

  3. 03

    怎么判断变好

    事先写下的标准

    每个实验开始前写下指标和成功标准，过程中不改。判断时对照原始记录，请 AI 或别人来判。还要在真实场景里检验，不能只在专门练习的时候有效。

    关键：人最容易在这里作弊：结果不好就换指标、找理由。所以标准要先写下，并且由别人来判。

  4. 04

    先改哪个

    每一轮的选择

    这一轮先多记录、先改环境，还是先刻意练习。

    规则：改了环境之后，旧的记录不再代表现在的你，要先重新记录一段。习惯养成后，删掉对应的提醒和规则。

  5. 05

    改进“改进方法”

    定期复盘方法本身

    每个季度回头看：实验选得好不好、指标准不准、复盘方式有没有用，然后调整。也在这时重新审视目标。

    固定不变的部分：价值观、底线，以及“修改评价标准要走单独流程”这条规则。

第三部分

人的数据从哪里来 通用方法

人不可能每天把所有事情写下来。基本思路是工具自动采集为主，人只补工具采不到的部分。具体用什么设备和软件因人而异，写在个人配置里。

数据类别回答什么问题常见来源能否自动采集
时间与行为时间花在哪，做了什么日历、屏幕使用时间、工作软件历史能
身体状态睡眠、恢复、活动量智能手表或手环、体重秤能
交流与环境和谁交流、交流了什么录音转写、会议纪要、消息记录能
产出与结果做成了什么任务完成、交付物、业务或交易结果大部分能
主观状态精力、情绪、满意度定时打分、随机时刻提问只能本人提供
执行记录实验有没有执行优先从上面几类自动推断，不行再打卡部分能
  1. 采集方式

    分四级，从上往下优先

    能用上一级解决的，不用下一级
    L1 被动自动设备和软件自动记录。只需一次性设置。例：手表记录睡眠、日历。
    L2 AI 起草，人确认AI 汇总自动数据写成日报，人只改错。每天约 1 分钟。
    L3 轻量主动打分、打卡、一句话。每次几秒。例：精力 1–5 分。
    L4 主动书写写日志、写复盘。只用于每周复盘。

    设计实验时：优先选能自动测量的指标。例如“11 点前睡觉”交给手表记录，有没有做到也能自动判断。

  2. 数据流程

    原始数据和摘要分开

    对应“评价标准不可修改”
    1. 自动采集
    2. →
    3. 原始数据（只读）
    4. →
    5. 统一格式
    6. →
    7. AI 汇总
    8. →
    9. 本人确认和打分

    AI 摘要可能出错，例如录音转写会有错字。判断实验效果时，必须能回到原始数据。

  3. 接入顺序

    先基线，再按需增加

    不先全量囤数据

    前 2–4 周只接自动来源，加每天一次打分，不做任何改变，用来了解平时的波动。之后每个实验只为它增加需要的数据。每个数据源都要说得出它回答哪个问题。

    隐私：原始数据只存本地；推送和分享只用摘要；涉及他人的录音和消息，事先写明保留什么、丢弃什么。

配置数据源适合谁
最低手机日历 + 手机屏幕使用时间 + 每天一次打分没有可穿戴设备，不想装软件
常规最低配置 + 智能手表 + 工作软件历史大多数知识工作者
完整常规配置 + 电脑使用记录 + 录音转写 + 业务结果数据愿意投入搭建，隐私规则明确

初步原则

落到 rsi-yourself 上的八条原则

  • 先能测量，再做改进选定领域后，先记录一段时间。
  • 一次一个实验写明改什么、做多久、怎么算成功。
  • 标准事先写下判断时对照原始记录，由 AI 或别人参与。
  • 看三样结果效果、有没有做到、付出的成本。
  • 关键行为靠机制环境限制、自动化、别人监督，比写规则可靠。
  • 规则库有上限习惯养成后删掉对应规则。
  • 只留能迁移的经验一次性的具体做法不写进规则库。
  • 新能力从外面学实验负责筛选和放大。
